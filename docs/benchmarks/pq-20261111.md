# PQ optimization measurements — 2026-11-11

Historical baseline: these staged results use `b083416`. The [current-main follow-up](pq-rq-fixes-20261111.md)
rechecks RQ after synchronization and calibrates the sparse-scan crossover.

Three improvements were implemented and benchmarked in order against
`b0834163e0e4ba2b6c859416d38b7e3c6529459e`. Each stage was built before the
next production change. The final version also compacts the transpose cache
and marks the sparse scan as a cold path. This report compares Paimon before
and after; it does **not** measure Paimon against a running Lance or Milvus.

Machine-readable [results](pq-20261111.json) retain Criterion estimates and
95% bootstrap intervals, all 24 ANN process samples, result signatures, source
hashes and the original `pq4_bench` output. The [CSV](pq-20261111.csv) contains
all 80 stage/case estimates. Criterion's iteration samples remain in
`target/criterion`; execution logs and per-stage binaries are in
`/tmp/paimon-pq-20261111` and `target/pq-stages` for this session.

## Industry comparison and selection

| Technique | Reference implementation | Paimon before this change | Action |
| --- | --- | --- | --- |
| Reusable transposed query targets | [Lance PQ](https://github.com/lance-format/lance/blob/main/rust/lance-index/src/vector/pq.rs) prepares L2 and dot targets; [Faiss PQ](https://github.com/facebookresearch/faiss/blob/main/faiss/impl/ProductQuantizer.cpp) supports transposed-centroid distance tables | A transpose cache existed for 8-bit batch encoding; query LUTs still used single-row SGEMM per subspace | Reuse one lazy, compact transpose for query LUTs and encoding |
| SIMD 4-bit lookup | [Faiss FastScan](https://github.com/facebookresearch/faiss/wiki/Fast-accumulation-of-PQ-and-AQ-codes-%28FastScan%29) uses short register LUTs; [Lance's current 4-bit path](https://github.com/lance-format/lance/blob/main/rust/lance-index/src/vector/pq/distance.rs) uses transposed f32-table SIMD | Block-layout FastScan had SIMD, but the persisted transposed reader's quantized suffix was scalar | Add NEON/AVX2 column lookup, retaining Paimon's existing hybrid exact/quantized scores |
| Apply selective filters before distance evaluation | [Milvus standard filtering](https://milvus.io/docs/filtered-search.md) narrows the ANN search scope before vector search | 8-bit had sparse scans; 4-bit still evaluated all list rows | Add sparse 4-bit row-major and transposed scans |

Milvus exposes PQ composition through its
[Knowhere/Faiss adapter](https://milvus.io/docs/faiss.md), including OPQ and
refinement recipes. Paimon already has OPQ, 4/8-bit PQ, precomputed residual
tables, batch table reuse, and blocked encoding; these are not counted as new
improvements. Raw-vector refinement and ScaNN-style anisotropic quantization
change the accuracy/storage budget and need a separate quality comparison.
They are not assumed to improve this same-configuration workload.

In particular, Lance's current f32 4-bit scan is not the same numerical
contract as Paimon's u8-quantized suffix. This change does not replace one
contract with the other to obtain a misleading speed comparison.

## Method

- Apple M4 Pro, 12 logical CPUs, 48 GiB RAM, macOS arm64; rustc 1.95.0.
- Release defaults, identical dependencies, no `target-cpu=native` or custom
  `RUSTFLAGS`. Benchmarks ran serially, without concurrent compilation/tests.
- `pq_query_bench`: Criterion, one Rayon thread, 30 samples, 500 ms warmup,
  2 s measurement per case, deterministic seed 42. Reported timings below are
  Criterion **mean estimates**. Confidence intervals are in the CSV/JSON.
- Reader cases: 128D, M=32, 4-bit, IP, 8 lists, 4 probes, top-10,
  **16 queries per timed batch**, 256 or 4096 rows/list. Random codebooks and
  codes isolate the reader; this benchmark checks output equivalence rather
  than recall. Filters select scattered IDs at 1%, 6%, 25% or 100%.
- Original `ann_bench`: clustered synthetic 10,000 × 64D, 4096 training rows,
  2048 queries, M=8, 8-bit, 64 lists, 8 probes, top-10, seed 42, two Rayon
  threads, local warm cache, at least 1 s each for sequential and batch timing.
  Six fresh-process samples/version alternate AB/BA. The base/final comparison
  is separate from the earlier base/step1 comparison.
- Original `pq4_bench`: 100,000 × 128D, 256 lists, 8 probes, 100 queries,
  M=16 for 8-bit and M=32 for 4-bit, two Rayon threads. Its recall check uses
  only 20 queries and its printed timing is coarse; it is a supplementary
  quality/smoke check, not the main timing evidence.

## 1. Reuse transposed codebooks for query LUTs

The fixed 16-centroid lanes let LLVM vectorize across centroids. This avoids
BLAS packing for each single-query subspace. L2 retains the expanded
`|q|² + |c|² - 2q·c` formula and clamping; IP retains the negative-dot score.
Canonical PQ encoding and the on-disk format do not change. Floating-point
summation order can change, so near-tie scores need not be bit-identical.

| L2 LUT, one query | Original µs | Step 1 µs | Speedup |
| --- | ---: | ---: | ---: |
| 128D / M32 / 4-bit | 2.257 | 0.273 | 8.27× |
| 128D / M16 / 8-bit | 11.711 | 1.825 | 6.42× |
| 768D / M96 / 8-bit | 68.284 | 12.587 | 5.42× |
| 768D / M16 / 8-bit | 53.190 | 9.615 | 5.53× |

The four IP cases improve 4.97–7.50× in this stage. Its independent six-pair
`ann_bench` run improved sequential QPS 24.6% and batch QPS 49.8%, with
Recall@10 unchanged at 0.4754. The final rerun below confirms the overall gain.

The cache adds up to `d * ksub * 4` bytes per quantizer after first use
(64 KiB at 64D/8-bit; 768 KiB at 768D/8-bit). Construction is lazy and adds
first-use work. Compact offsets avoid padding growth for irregular chunks.
No per-query transpose or allocation is needed after initialization.

## 2. SIMD lookup for the persisted 4-bit reader

The scalar quantized suffix now uses NEON `tbl` or AVX2 shuffle lookup.
Both contributions are widened before addition, preserving values up to
510 per pair. The exact first 200 rows, original float dequantization,
scalar tail, and large-M overflow fallback remain intact.

| 16-query batch, no filter | Step 1 µs | Step 2 µs | Speedup |
| --- | ---: | ---: | ---: |
| 256 rows/list | 206.423 | 179.966 | 1.15× |
| 4096 rows/list | 1950.078 | 552.535 | 3.53× |

All eight reader cases have identical result signatures (IDs and f32 score
bits) before and after this step. A reverse-order repeat measured the long,
unfiltered case at 551.289 µs for step 2.

## 3. Sparse filtered 4-bit scans

Only matching rows are evaluated below the existing sparse crossover:
at most 1/8 of a transposed list or 1/4 of a row-major list. The exact/quantized
decision uses the **original row position**, not its position in the filtered
subset. Quantization still covers the whole LUT. This preserves the prior
scores, including negative IP tables and overflow fallback. Scan-work counters
now account for sparse 4-bit evaluation.

| 16-query batch | Step 2 µs | Initial step 3 µs | Final µs | Final vs step 2 |
| --- | ---: | ---: | ---: | ---: |
| 256 rows/list, 1% match | 176.593 | 54.961 | 53.879 | 3.28× |
| 256 rows/list, 6% match | 176.858 | 68.641 | 69.347 | 2.55× |
| 4096 rows/list, 1% match | 421.463 | 187.811 | 200.505 | 2.10× |
| 4096 rows/list, 6% match | 456.861 | 411.389 | 454.452 | 1.01× |
| 4096 rows/list, no filter | 552.535 | 576.764 | 553.544 | 1.00× |

The initial unfiltered slowdown was reproduced (574.651 µs in a second run).
After marking the sparse helper cold and compacting the transpose cache, the
final unfiltered mean is within 0.2% of step 2's initial measurement. The 6%
long-list result does not demonstrate a material gain in the final run; the
strongest sparse benefits are at 1% and on short lists. All eight final result
signatures still match step 1 exactly.

## Final verification

| Original `ann_bench`, six-process medians | Base | Final | Change |
| --- | ---: | ---: | ---: |
| Warm sequential QPS | 25,376 | 31,389 | +23.7% |
| Warm batch QPS | 149,456 | 230,946 | +54.5% |
| Sequential P95, µs | 56.730 | 49.979 | −11.9% |
| Recall@10 | 0.4754 | 0.4754 | unchanged |
| Build, ms | 126.5 | 126.0 | similar |
| Add, ms | 5 | 5 | unchanged at reported precision |
| Index bytes | 175,029 | 175,029 | unchanged |

First-query medians were 96 µs base and 88 µs final in this run. Earlier
base/step1 samples were 78.5/84.5 µs, so a general cold-latency improvement is
not established. Peak process RSS also varied; no memory-reduction claim is
made. The transpose cache has the explicit memory cost described above.

For `pq4_bench`, base and step 1 both reported 36.5% recall for 8-bit and
34.5% for 4-bit, with 16 code bytes/vector. Full output is in the JSON.
The final reader microbenchmark is 3.71× faster without filtering at 4096
rows/list and 9.44× faster at 1% matching, relative to the original code.

Tests cover independent f64 distance oracles for 4/8-bit and balanced chunks,
cache replacement and compact irregular layouts, SIMD tails, full u16 sums,

stale caches and filtered-subset quantization. No numeric mutation score is
claimed. AVX2 was compile-checked, not executed or benchmarked on this ARM host.

## Reproduce

The added driver must be identical on both revisions. In a disposable baseline
checkout, copy `core/benches/pq_query_bench.rs` from the candidate and register
`[[bench]] name = "pq_query_bench", harness = false` in `core/Cargo.toml`.
Run each command in the appropriate checkout with separate output names:

```bash
RAYON_NUM_THREADS=1 cargo bench -p paimon-vindex-core \
  --bench pq_query_bench -- --save-baseline before
# After changing the implementation, use --save-baseline after.

RAYON_NUM_THREADS=2 ANN_DATASET_NAME=pq-clustered-v1 \
  ANN_N=10000 ANN_TRAIN_N=4096 ANN_NQ=2048 ANN_D=64 ANN_K=10 \
  ANN_NLIST=64 ANN_NPROBE=8 ANN_PQ_M=8 ANN_CLUSTERS=32 \
  ANN_NOISE_DIMENSIONS=64 ANN_SEED=42 ANN_INDEXES=IVF_PQ \
  ANN_STORAGE_CASES=local_ssd_warm_cache ANN_STEADY_MIN_MS=1000 \
  cargo bench -p paimon-vindex-core --bench ann_bench

RAYON_NUM_THREADS=2 cargo bench -p paimon-vindex-core --bench pq4_bench
```

For the ANN comparison, repeat six times/version in AB, BA, AB, BA, AB, BA
order using fresh processes. Unset inherited `ANN_*`, PQ timing/debug variables,
and `RUSTFLAGS` before reproducing the pinned configuration. The exact
per-process rows and ranges are retained in JSON; medians/ranges are
descriptive, not confidence intervals.

All measurements are synthetic and warm-cache. A public SIFT download did not
complete in this session; no real-embedding, cold-storage, x86 performance or
cross-product superiority claim is supported by these runs.
